# 与 MCTier 的功能对照与差距分析

> 参考对象：[pmh1314520/MCTier](https://github.com/pmh1314520/MCTier) v3.6.0
> （Tauri + React + TypeScript，约 190 个组件，Windows/Android 双端，基于 EasyTier + WebRTC）
>
> 本文档的目的：说清楚**我们有什么、它有什么、差距在哪、下一步先做什么**，
> 而不是罗列一张看起来很唬人的功能表。

## 0. 先说许可边界（重要，别踩坑）

MCTier 的 `LICENSE` 是**自定义的 Source-Available 非商业许可**，作者在 README 中明确说明
它**不符合 OSI 对「开源许可证」的定义**（因为禁止商业使用），并要求
「允许二次开发，但必须保留原作者信息；衍生项目需要按相同协议公开源代码」。

因此本项目对 MCTier 的做法是：

* ✅ **只借鉴功能范围与交互思路**（功能点、界面组织方式、用户流程 —— 这些属于「想法」）；
* ❌ **不复制任何源代码、样式表、图片资源、文案原文**；
* ✅ 所有实现由我们按自己的架构（主控 + 子节点 + 网页控制台 + Electron 客户端）
  独立编写，代码风格、数据结构、接口设计完全不同；
* ⚠️ 如果你打算**把这个平台商业化运营**，注意 MCTier 的限制**与我们无关**
  （我们没用到它的代码），但我们调用的 EasyTier 是 **LGPL-3.0**：
  以子进程方式调用、未修改其源码，因此不触发 LGPL 的传染性条款；
  分发 EasyTier 二进制时需随附其许可证与源码获取方式（`deploy/` 与客户端安装包里应带上）。

## 1. 架构层面的差异（这不是差距，是路线不同）

| 维度 | MCTier | mclink（本项目） |
| --- | --- | --- |
| 定位 | 通用虚拟局域网工具（游戏只是场景之一） | 面向《我的世界》玩家的联机平台（含运营能力） |
| 服务端 | 轻量信令服务器（只管大厅与成员映射，不转发数据） | **主控 = 信令 + 公共中继 + 运营后台**；另有**区域子节点**做就近中继 |
| 账号体系 | 无账号，靠大厅口令 | 有账号、角色、月度配额、封禁、审计日志 |
| 管理侧 | 无 | **网页管理控制台**（节点/房间/用户/流量/中继/审计/设置）+ 玩家落地页（含客户端下载） |
| 多区域 | 靠公共 EasyTier 节点 | 主控调度**自建子节点**，玩家按区域就近连接 |
| 流量能力 | 无平台级统计 | **按房间归因的流量统计 + 平台级/房间级限速**（已实测） |
| 私有化 | 支持自建信令服务器 | 设计上就是自建（你自己部署主控） |
| 客户端 | Windows + **Android** | Windows（Electron） |
| 前端技术 | Tauri + React | 网页端 Vite+Vue；客户端 Electron+Vue |
| 语言 | 中/英双语 | 中文（i18n 待做） |

一句话：**MCTier 更像是给个人用的组网工具，mclink 更像是给运营者用的联机平台**。
两边都有对方没有的东西，下面的对照只谈「它有的、我们还没有的」。

## 3. 本轮（本次提交）实际落地的内容

服务端：

* **房间聊天**：`room_messages` 表（迁移 V4）、历史/增量拉取、按码点截断（不切坏 emoji）、
  每人每房间每分钟 20 条限流、房主可删他人消息（记审计）、成员离开/被踢/审批自动生成系统消息、
  房间关闭时清空记录、7 天过期清理。
* 聊天只发给 `room:<id>` 话题，而该话题的订阅**要求是该房间的活跃成员**，
  因此闲聊不会外泄给非成员或匿名连接。

客户端（详见 `client/`）：

* `ChatPanel.vue` 房间聊天面板（未读徽章、表情插入、自己的消息可删、房主可删任意消息）
* `GameQuickConnect.vue` 游戏快连预设
* `ConnectionDiagnostic.vue` 连接诊断
* `PublicPlaza.vue` 公共广场
* `RoomShortcuts.vue` 收藏 / 最近
* `OnboardingWizard.vue` 首次使用向导

> 曾经实现过「主进程置顶迷你窗 + `MiniWindow.vue`」常驻显示联机地址，后按产品决定删除：
> 多一个置顶窗口会挡游戏画面，而玩家的真实动作只是「把地址发给朋友」——
> 现在 `RoomPage.vue` 的地址铭牌整块可点即复制，主进程不再有 `mini:*` IPC。

## 4. 建议的下一步优先级

**P1（下一步就该做，投入产出比最高）**

1. **Minecraft 世界自动发现** —— 直接决定「免输 IP」的体验；
   实现路径：客户端起一个 UDP 广播探测 + 对虚拟网段内每个成员做 Server List Ping（TCP 25565 握手），
   把 MOTD/版本/人数显示在房间页，一键复制或写入 `servers.dat`。
2. **高级网络配置界面** —— 服务端已能下发这些 flag，只差策略字段与 UI；
   属于「低成本放大产品力」。
3. **弹幕** —— 复用已有的 `room.message` 事件 + Electron 置顶透明穿通窗口。
4. **聊天图片** —— 需要先定文件存储策略（本地磁盘 + 每房间配额 + 大小上限），
   不要做成「无上限图床」。

**P2**：二维码邀请、头像、房间工具、全局快捷键、本地统计、版本检测、中英双语、文件夹共享（小文件）。

**P3（明确不做，理由是投入或风险）**

* 语音 / 变声 / 屏幕共享：需要 WebRTC 全套与音频设备处理，等于再做一个产品；
* Android 端：渲染层需重写；
* 远程控制：合规与安全风险高，收益不匹配。

## 5. 我们比 MCTier 多出来的东西（别在模仿中丢掉）

* 账号与权限体系（含封禁、角色、月度配额）
* **网页管理控制台**：节点、房间、用户、流量、中继、审计、平台设置
* **区域子节点调度**：主控按区域与负载下发中继，玩家就近连接
* **平台级流量统计与限速**（按房间归因，已用真实数据面实测）
* **单端口多房间隔离**，且网络名是密钥派生的不可猜测令牌
* 面向玩家的落地页与客户端下载分发
* 一键部署脚本（Debian x86）+ 子节点 agent

这些是「运营一个平台」才需要的能力，模仿免费工具时容易顺手丢掉。

## 6. 客户端运行时：深读 MCTier 的 EasyTier 拉起流程之后

> 参考文件（MCTier v3.6.0）：`src-tauri/src/modules/network_service.rs`（约 2200 行）、
> `virtual_network.rs`、`easytier_advanced_commands.rs`。行号按该版本标注。
> 阅读目的只有一个：**它踩过的坑我们不要再踩一遍**。

### 6.1 它怎么拉起 easytier-core（源码事实）

| 做法 | 位置 | 说明 |
| --- | --- | --- |
| 组装**命令行参数**，不用 TOML 文件 | `network_service.rs` 全文 | 我们用「TOML + `-c`」，它用 `--flag` 一把梭；两种都受支持 |
| **从不设置** `--enable-udp-broadcast-relay` | 全文件搜索无此参数 | 它的默认值就是关；这正是我们上轮把广播直通改为**默认关**的依据 |
| 固定网卡名 `--dev-name MCTier_Net` | L300-303、L2154 | 每次连接复用同一张网卡，玩家在系统里认得出 |
| RPC 端口**动态探测**，随机化起点 | L638-643、L850 | 注释写明：避免二次使用时端口粘连导致 **os error 10013** |
| RPC 显式绑回环 `127.0.0.1:<port>` | L795-796 | 注释写明：裸端口会被绑到 0.0.0.0，撞上 Windows 保留端口段 → 10013 |
| 启动前**清理孤儿进程**，并等 TUN 释放 | L1184-1209（类 Unix `pkill` 按可执行名）、Windows 侧走提权小助手 | 注释写明：残留进程会占着 TUN 与端口 |
| 子进程 `kill_on_drop(true)` | L890、L959 | Rust 侧保证随对象销毁而终止 |
| 同时用 `--dhcp` / 静态地址两种模式 | 高级命令模块 | 我们固定下发静态虚拟地址（平台要按 IP 做 ACL 与统计） |

### 6.2 差距 → 本轮补上的部分

| 问题 | 它怎么解 | 我们之前的状况 | 现在的做法 | 验证 |
| --- | --- | --- | --- | --- |
| Windows 上网卡越攒越多、认不出哪张是联机用的 | 固定 `--dev-name` | 交由系统命名，重装/重启可能多出「以太网 3/4」 | 票据里写死 `dev_name = "McLink"`（[`rooms.ts`](../server/src/services/rooms.ts)） | lab：读磁盘上真实生成的 `client-*.toml`，断言 `dev_name = "McLink"` |
| 客户端崩溃后残留 core 占着端口与网卡 → 下次启动 `failed to listen (10048)` | 启动前 `pkill` + 等 TUN 释放 | 无任何清理 | 启动 1.2 秒后清理，判定条件**同时**要求「可执行文件在本应用 vendor 目录」且「命令行里出现本客户端数据目录」 | 真机实测：先手工造一个孤儿核心再启动客户端 —— 孤儿消失、主控中继存活、客户端日志出现「已清理上一次残留的 easytier-core 进程 1 个」 |
| 「连接」与「应用 ACL 后重启」两条路径交错 → 两个 core 抢同一端口（实测相隔 261ms） | 单一服务对象 + Rust 所有权天然串行 | 两个 IPC 入口各自 await，可能交错 | 所有启停进同一条 Promise 链（`withCoreLock`），并把 `core:stop` 也纳入队列 | 真机实测：并发发起两次 `core.start`，两次都返回 `running`，磁盘上只存在一个核心进程，日志无 10048 |
| 端口类错误的提示指错方向 | 日志里直接写 os error 与排查清单 | 10048 会被「网卡绑定被拒绝」分支吃掉，引导玩家去点提权 | 端口错误单独成支，排在 `bind` 判断之前，并给出「关掉其它虚拟网络软件」的建议 | [`store.ts`](../client/src/lib/store.ts) `describeCoreError` |
| Windows 保留端口段导致 RPC 绑不上（10013） | 动态探测 + 随机起点 + 显式回环 | 由主控按 `16000 + listenPort % 1000` 推算，落在固定段内 | **客户端上报**探测到的 RPC 端口，主控只校验范围（1024–65535），非法值回退推算 | lab 三条：采纳上报值 / 非法值回退 / 始终 127.0.0.1 |

第一次绑定失败会自动清理并重试一次（`MAX_START_ATTEMPTS`）；重试仍失败则明确报
「监听端口被占用」并停止核心——**不假装已连接**。重试期间主动标记 `coreRestarting`，
避免「我们主动停的」被当成「核心自己崩了」而再排队一次自动重启。

> 实现期间踩到的两个坑，都已写进代码注释：
> 1. **这台机器的 WMI 会偶发 `远程过程调用失败 (0x800706BE)`**，命令整体失效、
>    stdout 为空，清理就静默失效（第一次测孤儿清理就是这么假通过的）。
>    现在 CIM 失败会回退 `Get-WmiObject`，整体失败还会重试一次并写日志。
> 2. PowerShell 里 `try { } ; catch { }` 是**语法错误**：脚本片段必须用换行拼接，
>    用 `'; '` 拼会直接解析失败（Node 传参时不会替我们发现这个问题）。

### 6.3 我们刻意**不跟**的两点

* **`--bind-device true`**：它默认开启。我们相反，所有角色都显式关闭 ——
  EasyTier 默认 `bind_device = true`，在受限容器/多网卡/沙箱环境下会直接
  `WSAEADDRNOTAVAIL(10049)`，玩家表现为「连上主控却进不了房间」
  （见 [architecture.md](architecture.md) 的实测记录）。这是环境差异，不是谁对谁错。
* **提权小助手进程**：它的 Windows 侧用「窄权限助手」做网卡物化与清理。
  我们的做法更简单：检测到未提权就在界面与日志里说清楚，让玩家用
  「以管理员身份重启」——少一个需要维护的提权通道，也少一处签名/权限风险。

### 6.4 还没做、值得记一笔的

* **Minecraft 世界自动发现**（上文 P1）：它靠这个把「免输 IP」做完整。
* 我们的 RPC 端口段是 `16000–16999`，上报值优先后只剩「客户端没上报」的
  兼容路径才会用到它；若将来出现同机多实例的运营场景，再考虑持久化端口分配表。
* 它的 `--dev-name` 是**首次运行写入配置、之后从配置读回**；我们的名字来自票据，
  属于服务端下发，改一次全网生效——这是平台化带来的便利，也是约束
  （玩家不能自己改网卡名）。
