# 1.1.0 —— 更新说明

> 客户端与服务端版本号同步为 **1.1.0**。本次是**修复版**：主控侧的中继模型已经换代，
> 客户端只跟着改了一处**标注文案**，不需要玩家做任何操作。

## 给玩家的说明（可直接发公告 / 群发邮件）

**修好了：房间里有「上海阿里云」这类节点时，有人连不上、走不了中继的问题。**

之前有玩家反馈：房间里明明是两台中继，却怎么都连不通，或者只有一部分人能进。
排查下来不是网络问题，而是**平台把"该由哪台中继转发"交给了 EasyTier 自己选**，
而它在这条链路上会选错 —— 选中的那台恰好是**不承载数据**的节点，于是数据被丢掉、
房间整片不通。这个问题在有上海阿里云节点参与的房间上更容易碰到。

现在改成**由平台直接指定**：

* 每个房间固定分配**最多 3 台中继**，房主会把这 3 台都连上；
* 其他成员进房时，平台按**当前哪台最空**给每个人指定 1 台 —— 每个人固定走自己那台，不再靠内核去选；
* 小带宽的节点一旦忙到自己的线，就**不再接新房间**（已经在里面的人不受影响）；
* 某个房间确实忙起来时，**后来进房的人会自动被分到更空的那台**，房里的人不用动。

顺带修的：房间页里的中继标注以前会写成「打洞节点」，现在**统一显示为「中继节点」**。

**需要做什么**：更新客户端即可（老版本也能正常联机，只是房间页的标注会显示得不准）。
如果你正在房间里，**退出重进一次**就会用上新的中继分配。

### 上线步骤

```bash
cd /opt/src/mclink && git pull
sudo bash "$PWD/deploy/install-server.sh" --skip-install --skip-web
```

1. 让**正在开的房间的房主退出重进一次**（房主旧票据里只有老中继，新成员分到别台就到不了它）；
2. 之后新房间全自动；客户端按常规发版节奏推送即可（老客户端同样能玩）。

### 已知限制

* 成员之间**不互相直连**（房主开服场景无影响；各成员到房主都是固定两跳）；
* 平台设置里的「房间中继过载阈值」现在是**上限**，实际按每台节点自己的卸荷线取小值；
* 控制台房间详情里「有节点不在调度名单里（正在顶班）」这句在新模型下是**正常状态**，
  文案待改准确（见 `docs/relay-assignment.md` 的待办）。
