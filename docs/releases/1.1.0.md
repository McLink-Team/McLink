# 1.1.0 —— 更新说明

> 客户端与服务端版本号同步为 **1.1.0**。本次是**修复版**：主控侧的中继模型已经换代，
> 客户端只跟着改了一处**标注文案**，不需要玩家做任何操作。

## 给玩家的说明（可直接发公告 / 群发邮件）

**修好了：房间里有「华东-A」这类节点时，有人连不上、走不了中继的问题。**

之前有玩家反馈：房间里明明是两台中继，却怎么都连不通，或者只有一部分人能进。
排查下来不是网络问题，而是**平台把"该由哪台中继转发"交给了 EasyTier 自己选**，
而它在这条链路上会选错 —— 选中的那台恰好是**不承载数据**的节点，于是数据被丢掉、
房间整片不通。这个问题在有华东-A节点参与的房间上更容易碰到。

现在改成**由平台直接指定**：

* 每个房间**只连一台中继**，房主和所有成员的票据里都是同一台 —— 房间里没有第二条可被误选的路；
* 一台节点到容量上限时，房间里会出现提示（新版客户端还会响一声「叮咚」）：
  **房主**看到「立即切换」按钮，**成员**看到"需要房主更换"；房主切完后成员点「重连」跟上（各断几秒）；
* 如果房间里所有人都是**直连（P2P 打洞）**，流量不经过中继 —— 那就不发任何提示；
* 小带宽的节点一旦忙到自己的线，就**不再接新房间**（已经在上面的人不受影响）。

顺带改清楚的：房间页里的中继标注以前会写成「打洞节点」，现在**统一显示为「中继节点」**；
中继那一栏的标题旁会写明「本机票据 N 台」。

**需要做什么**：更新客户端即可（老版本也能正常联机，只是房间页的标注不准、
且听不到那条「叮咚」提示音）。

### 上线步骤

```bash
cd /opt/src/mclink && git pull
sudo bash "$PWD/deploy/install-server.sh" --skip-install --skip-web
```

1. 让**正在开的房间的房主退出重进一次**（房主旧票据里只有老中继，新成员分到别台就到不了它）；
2. 之后新房间全自动；客户端按常规发版节奏推送即可（老客户端同样能玩）。

### 已知限制

* 一台中继到线时只能**整房搬走**（房主先切、成员再重连），不能像"多台"那样把新成员摊开 ——
  这是用"路径可控"换来的取舍（见 `docs/relay-assignment.md` 的"为什么退回 1 台"）；
* 一直不点「重连」的成员，在房主切换后会连不上（旧节点已经没有到房主的路）——
  系统消息与横幅都写明了这一点；
* 平台设置里的「房间中继过载阈值」现在是**上限**，实际按每台节点自己的卸荷线取小值；
* 成员在房间页能看到的中继只有一台（这就是单节点模型的意义）。
