## 正文（纯文本，可直接粘贴）

```
尊敬的 McLink 用户：

您好。

McLink 客户端 1.0.9 已发布（Windows 与 macOS 同步），安卓版同步更新到 1.0.5。本次更新说明如下。

一、每个房间现在有两台机器分工

以前平台给每个房间配两台中继，但没有分工。现在改成：

· 一台「打洞节点」：负责帮你和朋友直接连上（交换双方的公网地址），
  它不承载游戏流量；
· 一台「中继节点」：直连打不通的时候，游戏流量走这一台。

在房间里点开「连接路径」，这两行现在会分别标注「打洞节点」和「中继节点」，
一眼能看出哪台在干活。

二、中继挑选规则更合理

中继节点从"带宽够大"的节点里挑（默认 10 Mbps 以上；没填带宽上限的节点视为不限）。
带宽比较小的节点跑到 80% 就不再接新的房间 —— 它上面已经开着的房间不受影响，
只是不再往它身上加新房间，避免把正在玩的人一起拖慢。
另外某个区域如果只部署了打洞节点，平台会自动从邻近区域调一台中继过来，
不会出现"这个区域开不了房"。

三、房间太挤的时候，平台会问你要不要换

如果某个房间走的中继持续拥堵，平台会准备好一台更空闲的大带宽机器，
然后在你的客户端里弹一条提示，问你要不要切过去。
切过去会重建连接、卡顿几秒，所以由你自己决定什么时候切 ——
你正在打重要进度的时候完全可以点「稍后」。
（房间里也会留一条系统消息，方便事后追溯。）

四、流量统计修好了

控制台的「今日 / 本月 / 累计流量」和「按用户用量」以前会归零或一直显示 0，
现在改成真实累计：重启中继不再清零，一个房间有多台机器在转发也会正确相加。
流量页新增「字节账本」曲线（每分钟 / 近 30 天）与「按用户」明细。

五、安卓客户端 1.0.5

与桌面端同批更新：房间页同样显示「打洞节点 / 中继节点」，
中继建议提醒同样支持（由你自己决定切不切）。

六、macOS 用户请注意

请在下载页重新下载 dmg 覆盖安装。旧版 mac 客户端里的「立即更新」会指向
Windows 安装包（那是上一版的问题，本版已修正，不会再出现）。
首次打开若提示"无法验证开发者"，在访达（Finder）里右键点图标、选「打开」即可 ——
我们暂未购买 Apple 开发者签名，这一步只需做一次。

下载地址：https://cnnic.link/download

本次更新不需要你做任何手工配置：Windows 与安卓覆盖安装即可，
macOS 把 dmg 里的 McLink 拖进「应用程序」覆盖。
如果遇到问题，请在客户端的「连接诊断」里复制信息后联系我们。

感谢你的支持。

McLink 团队
```

1. ✅ 产物已上传（2026-09-29 线上核对）：`McLink-Setup-1.0.9-x64.exe`（桌面）、

   这一条从外部看不到，发公告前自己在控制台瞄一眼。
3. ✅ 主控已是最新（线上 `version` = `1.0.9`，说明 V21 → V24 迁移已跑过）。
4. ✅ `https://cnnic.link/api/v1/meta`：`clientVersion` = `1.0.9`、`version` = `1.0.9`、
   `clientDownloadUrl` = `/downloads/McLink-Setup-1.0.9-x64.exe`（实测值见文首）。
5. 控制台 →「平台设置」：确认 `大带宽档门槛`（默认 10 Mbps）、`小带宽节点卸荷线`（默认 80%）、
   `房间中继过载阈值`（默认 8 Mbps）三个值符合预期 —— 迁移不会覆盖这三个（它们不在迁移里）。
6. 每个节点的「带宽上限」按云厂商口径填好（不填 = 不限 = 算大带宽）；
   带宽很少的机器在**低峰**把「只协助打洞」打开（会让它重启一次核心，秒级）。
7. 建房验证一次：房间页「连接路径」那两行应分别显示**打洞节点 / 中继节点**。
8. 发公告（站内信 / 邮件 / 短信）—— 产物与主控都已就绪，随时可发。
