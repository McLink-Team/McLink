## 发布检查单

1. ✅ 产物已上传（2026-09-29 线上核对）：`McLink-Setup-1.0.9-x64.exe`（桌面）、
   `McLink-1.0.9-macos-arm64.dmg` + `McLink-1.0.9-macos-x64.dmg`（macOS，**GitHub Actions 从 `main` 出**，
   见上面的说明与 docs/build-clients.md 的 1.2）、`mclink-android-1.0.5-debug.apk`（安卓）。
   mac 的 zip **没有上传也不需要**：下载页主推 dmg（`preferDmg`）。
2. ⚠️ 控制台 →「节点」：**至少一台 `online` 的子节点**（单机部署就把主控注册成节点）。
   这一条从外部看不到，发公告前自己在控制台瞄一眼。
3. ✅ 主控已是最新（线上 `version` = `1.0.9`，说明 V21 → V24 迁移已跑过）。
4. ✅ `https://cnnic.link/api/v1/meta`：`clientVersion` = `1.0.9`、`version` = `1.0.9`、
   `clientDownloadUrl` = `/downloads/McLink-Setup-1.0.9-x64.exe`（实测值见文首）。
5. 控制台 →「平台设置」：确认 `大带宽档门槛`（默认 10 Mbps）、`小带宽节点卸荷线`（默认 80%）、
   `房间中继过载阈值`（默认 8 Mbps）三个值符合预期 —— 迁移不会覆盖这三个（它们不在迁移里）。
6. 每个节点的「带宽上限」按云厂商口径填好（不填 = 不限 = 算大带宽）；
   带宽很少的机器在**低峰**把「只协助打洞」打开（会让它重启一次核心，秒级）。
7. 建房验证一次：房间页「连接路径」那两行应分别显示**打洞节点 / 中继节点**。
8. 发公告（站内信 / 邮件 / 短信）—— 产物与主控都已就绪，随时可发。
