> **给运营的说明，不要粘进公告里。**
>

## 这一版实际包含什么（工程记录）

| 项 | 说明 |
| --- | --- |
| 联机 | `libeasytier_android_jni.so`（EasyTier v2.6.4，commit `8428a89`，与桌面端同一 commit）交叉编译而来，arm64-v8a，单库自包含；从上游源码构建的构建实录见 `android/native/README.md` §9 |
| VpnService | 前台服务（`specialUse`）+ 授权流程；八条硬规则见 `docs/android-vpn.md` §4（空路由绝不 establish、永不 `0.0.0.0/0`、只路由房间网段、不劫持 DNS、`startForeground` 先于 establish、`onRevoke` 等） |
| 踢人 | ACL 施加走"合并进配置 → 重启内核实例"（与桌面端 2.6.4 的回退路径同一条，因为 2.6.4 没有 `acl set` 热更新）。**房主自己断线约 2 秒** |
| 改昵称 | 复用与桌面端同一套校验（`@mclink/shared` 的 `displayNameProblem`，含保留词/冒充防护） |
| 更新提示 | 安卓只认自己的产物（`clientDownloads.android`），不会再把桌面端的版本号（1.0.7）当成"新版本"提示 |

### 三个必须记住的坑（都写进代码注释与文档了）

1. **`.so` 必须查未定义符号**：上游 v2.6.4 的 JNI crate 只在 `extern "C"` 里声明 FFI 函数，
   不写 `extern crate easytier_ffi;` 的话整块实现不会链进去 —— **编译成功**、装机 `dlopen` 才失败
   （0.2.0 的真实事故）。门禁：`android/scripts/check-undefined-symbols.mjs`，
   并被 `verify-android-apk.ps1` 第 5 组检查从 APK 内的 `.so` 上再跑一遍。
2. **`.so` 体积是信号**：空壳 6.29 MB，真链上 19.93 MB。体积突然变小要当故障查。
3. **安卓不能拿桌面端的 `clientVersion` 比版本**（会导致"有新版本 1.0.7、点开是 .exe"）。

## 发版顺序（与桌面端同样的纪律）

1. 把 `mclink-android-1.0.0-debug.apk` 传到主控的 `data/downloads/`，删掉旧的 0.1.0 / 0.2.x
2. 服务器上 `git pull` + 重跑 `install-server.sh`（会构建 `server/public` 并跑迁移）
3. 打开 <https://cnnic.link/download> 确认安卓卡片显示"版本 1.0.0"、链接指向新 APK
4. 再发公告
