# McLink 1.0.8 更新公告（邮件格式）

> **给运营的说明，不要粘进邮件里。**
>
> 主控的「邮件公告」只发**纯文本**（`mailer.sendAnnouncement(to, subject, text)`，没有 HTML 正文），
> 所以下面正文里的 `·`、`1. 2. 3.`、空行就是最终呈现的样子，不要加 Markdown 的 `**`、`#`、表格。
>
> 安装包地址：<https://cnnic.link/downloads/McLink-Setup-1.0.8-x64.exe>
> ⚠️ 发信前先确认这个文件已在主控的 `data/downloads/` 里，否则邮件里的链接会 404。
> 上传顺序：**先传安装包 → 再 `git pull` + 重跑 `install-server.sh`**（V21 迁移把默认版本与下载地址
> 改成 1.0.8）**→ 最后才发公告**。
>
> ⚠️⚠️ **本次主控必须先确认"至少有一台可调度的子节点"，再更新！**
> 1.0.8 取消了"主控自己当中继兜底"这条老规矩：票据里的中继**全部**来自 `relay_nodes` 里
> 状态在线、未禁用、权重 > 0 的子节点。一台都没有时，建房会直接返回
> 503「当前没有可用的中继节点，暂时无法建房」——**所有玩家都开不了房**。
> 单机部署的补法：把主控自己注册成一台普通子节点（控制台 →「节点」→ 签发密钥 →
> 在服务器上跑安装命令，`--endpoint` 填这台机器的公网地址与链接端口），
> 然后确认它在列表里是 `online`。详见 `deploy/README.md` 与 `docs/deployment.md`。
>
> ⚠️ **主控与客户端要一起更新。** 票据形态、中继调度与徽标语义都在这一版换掉了：
> 主控还是旧代码时，票据里仍会多一条"主控兜底"，新客户端会把它标成「兜底」并排在第二行；
> 反过来，客户端还是旧版而主控已更新时，老客户端不发延迟提示，调度会退化成"权重优先"——
> 能玩，但不是这一版想要的排序。
> 判据：`https://cnnic.link/api/v1/meta` 的 `clientVersion` 变成 `1.0.8`。
>
> 📌 **主控本轮发 1.1.0**（版本线与客户端独立）：`/meta` 的 `version` 会变成 `1.1.0`，
> 控制台「平台版本」也跟着变。这次主控侧跑了两个迁移：**V21**（默认客户端版本/下载地址
> → 1.0.8）与 **V22**（新建流量账本表 `traffic_ledger`，并清空旧口径的 `room_usage`）。
> V22 之后控制台的「今日 / 本月 / 累计流量」与「按用户用量」才是真实累加值 ——
> 以前房间累计是"覆盖写"（中继一重启就归零），用户维度恒为 0。
>
> 校验值：本机产物 `McLink-Setup-1.0.8-x64.exe` 91,978,738 字节，
> sha256 `8fccf3f5ab7831b0cee17d89a182d8938d4c5f8e345a059f94cc072f664ea68f`。
> 若改用 GitLab CI 出的包（`deploy/fetch-release-from-gitlab.sh`），**以那个脚本打印的 sha256 为准**
> —— CI 重新打包的 exe 与本机产物的哈希不会相同（时间戳等元数据不同），两者都能装。

## 正文（纯文本，可直接粘贴）

```
尊敬的 McLink 用户：

您好。

McLink 客户端 1.0.8 已发布。这一版改的是"房间里走哪台中继"这件事，现说明如下。

一、每个房间现在有两台中继：主中继 + 兜底中继

以前平台会给每个房间额外挂一个"主控兜底入口"。这个做法的问题是：
兜底那台是固定的，它一旦拥堵或线路抖动，房间该慢还是慢。

现在改成给每个房间分配两台不同的中继节点：一台主中继、一台兜底中继。
平时业务流量走主中继；主中继不可用时，兜底那台会接管，房间不会因此断开。
兜底不是写死的：节点状态一变，平台会在下一张票据里重新挑一台，
优先挑延迟低、剩余带宽多的节点。

顺带说明挑选规则：先看运营方给的权重（专线节点权重更高），
权重相同时才比延迟；延迟差别在 5 毫秒以内的节点视为同一档，
这一档里挑剩余带宽最多的那台。

二、建房页的延迟不用再等了

旧版是"你点开建房页才开始测各个节点的延迟"，所以要盯着「—」等一会儿。
1.0.8 改成登录成功后就把所有节点测完，建房时直接读结果。

另外，房间里那两台中继的显示也修正了：以前两台上都有几 KB 的保活流量，
界面会把它们都标成"承载流量"，看起来像同时连了两台服务器。
现在按实际角色标注「主中继」和「兜底」，一眼能看出哪台在干活。

三、安卓客户端 1.0.4

安卓端本次同步更新：

· 真正支持联机（此前安卓版只是外壳，无法进房）
· 房主可以在成员列表里踢人
· 房间页补齐链路、节点与延迟数据
· 设置页可以修改昵称

下载地址：https://cnnic.link/download

本次更新不需要你做任何手工配置，覆盖安装即可。
如果遇到问题，请在客户端的「连接诊断」里复制信息后联系我们。

感谢你的支持。

McLink 团队
```

## 发布检查单

1. `McLink-Setup-1.0.8-x64.exe` 已进主控 `data/downloads/`（macOS 的两个包同目录，官网自动识别）。
2. 控制台 →「节点」：**至少一台 `online` 的子节点**（单机部署就把主控注册成节点）。
3. 主控已 `git pull` + 重跑 `install-server.sh`（跑 V21 + V22 迁移）。
4. `https://cnnic.link/api/v1/meta` 的 `clientVersion` = `1.0.8`、`version` = `1.1.0`
   （后者是主控自己的版本线），`clientDownloadUrl` 指向新安装包。
   顺手看一眼控制台「流量监控」：今天有房间跑过之后，「今日流量」应该是个**会持续增长**的数，
   而不是 0 或者"重启就归零"。
5. 控制台 →「平台设置」：若 `clientDownloadUrl` 仍指向旧文件名（管理员手改过，迁移不会覆盖），
   手动改成 `/downloads/McLink-Setup-1.0.8-x64.exe`。
6. 发公告（站内信 / 邮件 / 短信）。
7. 公告发出后随手上传安卓 `mclink-android-1.0.4-debug.apk`，下载页的安卓卡片会自动换版本号。
