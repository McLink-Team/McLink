# 私有化部署：自己跑一套 McLink

2026-10-07 起官方不再提供中继与公益转发服务。这份文档是"自己搭一套"的最短路径，
顺序就是落地页那段「自建一套要做什么」展开后的内容。

> 已经有一台能跑 Node 的 Linux 服务器就够。**中继节点和主控可以是同一台，也可以分开**；
> 只是"中继"必须是一台有公网端口的机器（它负责给房间转发流量）。

## 一、装主控

```bash
git clone https://github.com/example/backup.git
cd mclink
sudo bash deploy/install-server.sh
```

安装脚本会：建 `mclink` 系统用户、拉依赖、建 SQLite 库、装 systemd 服务 `mclink-server`、
在 `/etc/mclink/mclink.env` 写初始环境变量（含首次生成的管理员密码与中继端口）。

装完在浏览器打开 `http://<你的域名或IP>/`，用 `admin` + 环境变量里的密码登录控制台。

## 二、注册你自己的中继节点

节点就是转发服务器（一个房间一台，主控按延迟就近挑）。在**节点那台机器**上：

```bash
# 主控控制台 →「节点」页 → 生成接入密钥，然后：
sudo bash deploy/install-node.sh --master https://<你的主控> --enroll-key <接入密钥>
```

节点会在 20 秒内出现在控制台的「节点」页，状态变成 **在线**。别忘了：

* 节点要填**带宽**（控制台节点编辑里的「带宽上限」）。不填当作不限；
  填了之后平台会按它算卸荷线（小管子 80%、其余 90%），到线时房间里的玩家会收到"可切换到更空闲节点"的提示。
* 云厂商的安全组要放行节点的**链接端口**（默认 11010，TCP+UDP 同端口）。

## 三、把实例收成"私有"

控制台 →「平台设置」：

| 字段 | 建议值 | 作用 |
| --- | --- | --- |
| 注册模式 | **仅邀请码** | 注册必须带有效邀请码；在「邀请注册」页生成后发给朋友 |
| 本实例对公众开放 | **关** | 落地页换成"已停止对外服务"那一版：不再招徕使用者，改为仓库地址 + 自建指引 |
| 停止对外服务的日期 | `2026-10-07` | 只用于文案（落地页与公告），不参与任何判定 |
| 项目仓库地址 | 你的仓库地址 | 落地页"看源码 / 自建"按钮指向它 |
| 平台公告 | 一句话说明 | 显示在落地页顶部公告条里 |

**注册模式三态**（都会同步到老客户端读的 `registrationOpen`，所以不需要玩家升级客户端）：

* `open` —— 谁都能注册（公测期的老行为）；
* `invite` —— 必须带邀请码（**私有实例推荐**）；
* `closed` —— 完全关闭，只能管理员在控制台建号。

邀请码在控制台「邀请注册」页生成：可写备注（发给谁）、设可用次数（0 = 不限）与有效天数。
发给朋友的注册链接形如 `https://<你的主控>/register?invite=ABCD2345EF`。

## 四、让玩家连上你的实例

客户端默认连官方主控地址。私有实例有两种用法：

1. **网页注册 + 客户端登录**：玩家在 `https://<你的主控>/register` 用邀请码注册，
   然后在客户端里……**目前客户端的主控地址是打包时写死的**，
   所以自建实例需要自己出一版客户端：构建时设 `VITE_MCLINK_MASTER=https://<你的主控>`：

   ```bash
   pnpm install
   VITE_MCLINK_MASTER=https://<你的主控> pnpm dist:client     # Windows 安装包
   ```

   安卓与 macOS 的构建方式见 `docs/build-clients.md`（安卓的地址写在自己的 `.env`/构建脚本里）。
2. **局域网直连**：同一路由器下的玩家本来就不需要主控（P2P 打洞），
   但**建房/进房仍然要经过主控**签发票据，所以这条也要先有主控。

> 换句话说：私有实例 = 主控 + 至少一台中继节点 + 一版把主控地址指向你的客户端。
> 三者都齐了，玩家体验与官方实例完全一致。

## 五、日常运维

* 升级：`cd mclink && git pull && sudo bash deploy/install-server.sh --skip-install --skip-web`
  （改过前端才需要 `--skip-web` 之外的重建；主控会自动跑数据库迁移）。
* 备份：整个 `server/data/` 目录（SQLite 库 + 下载目录）就是全部状态。
* 版本一致性：仓库里有一条 `pnpm check:versions`，把 6 个 `package.json`、
  安卓 `build.gradle` 与主控的 `APP_VERSION` 钉在一起 —— 出客户端前跑一次，避免"装的是新版、显示是旧版"。
* 排障入口：控制台「仪表盘 / 流量 / 审计」，以及 `journalctl -u mclink-server -f`
  （中继调度、到线通知、邀请注册都会写日志）。
