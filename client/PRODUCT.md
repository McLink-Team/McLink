# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

（本目标 = Electron 桌面客户端 `client/`：Web 技术渲染 + 原生窗口外壳，按 `web` 平台处理；
另有同仓库的官网/管理台 `web/` 与服务端 `server/`，不属本目标的改造范围。）

## Users

**主用户：想和朋友联机的玩家。** 场景是"今晚约好了开一局"——几个人分散在不同城市、
各自在家里的 Windows 机器上，谁都没有公网 IP，也不想装组网工具、不想改路由器。
他要做的事只有三件：建一个房间、把地址给朋友、确认朋友进来了且不卡。

**次用户：自己把主控跑起来的人**（可能是玩家中的一个人，或一个小社区的管理员）。
他要的是"一条命令装完、能看见谁在用、出事能查"。

## Product Purpose

把"局域网联机"这件事从**网络工程问题**降级成**发一个地址**：主控 + 区域中继 + 客户端托管
EasyTier 组网，玩家侧零配置——不需要公网 IP、不需要端口映射、不需要装组网工具。

成功的样子：第一次用的玩家在不看文档的前提下走完"建房 → 朋友进房 → 在游戏里看到对方"，
中途不需要向任何人求助；出问题时界面能说清是"谁的哪一段"有问题。

## Positioning

**一台主控、一个端口，承载所有房间。** 中继按网络名（`relay_network_whitelist = "mclink-room-*"`）
决定是否转发，于是新建/关闭房间都不需要重启中继、也不需要为每个房间分配端口。
这是同类"联机平台"要么做不到、要么要靠一房间一进程/一端口硬撑的地方。

第二条：**客户端不是组网工具**。网络身份、虚拟地址、中继列表、启动参数全部由主控下发，
玩家侧没有"配置"这个概念。

## Operating Context

- 客户端是 Windows 桌面应用（Electron，单实例，托盘常驻），窗口默认窄幅单列。
- 玩家的真实动作顺序：登录 → 建房/进房 → **把地址复制出去**（微信/QQ/语音里发给朋友）→
  在游戏里连接这个地址 → 盯着成员列表与延迟，直到所有人都在。
- **游戏在另一个窗口里全屏跑着**：客户端是被切出去看一眼就切回来的那种窗口，
  不是会长时间盯着看的界面。信息要在一眼里读完。
- **建虚拟网卡需要管理员权限**，而玩家通常不是管理员 → 权限引导必须在客户端里解决，
  不能让人自己去翻设置。
- 主控由用户自己部署（Debian 12 + nginx 反代），客户端里嵌的官方主控地址是
  `https://cnnic.link`；平台不开放第三方自建主控接入客户端。
- 中文界面（简体），术语以仓库为准：房间/加入码/主控/中继/子节点/票据/虚拟地址/加入码。

## Capabilities and Constraints

- 客户端能力：登录注册与邮箱验证、建房（6 位加入码、可选密码或房主审批）、加入、房间成员与
  延迟/P2P 状态、房间聊天、游戏快连预设、连接诊断、公开广场、收藏与最近、设置（含管理员
  权限引导与主题）。
- 硬约束：
  - 一切颜色/字号/间距/圆角/动效只来自 `packages/shared/src/design/tokens.css`，
    页面与组件里**不出现十六进制或 `rgba(...)`**；
  - 客户端与官网页共享同一份令牌层，两边不能各自长出一套；
  - 设计检查器（Impeccable detector）必须在改动范围内 0 findings；
  - 正文字号不小于 12.5px；有文字且有边框/底色的元素垂直内边距 ≥4.3px；
    长字符串（hash/ID/URL/配置片段）必须能完整换行，不许截断成省略号；
  - 客户端离线可用：字体不得依赖 CDN。
- 明确未定：本轮不动官网（`web/`）与服务端（`server/`）的视觉；
  客户端的房间页/设置页只做"在新外壳下不崩、不被挤坏"，不做重新设计。

## Brand Commitments

- 名称 **McLink**；对外一句话：**"基于 EasyTier 的局域网联机平台，支持《我的世界》等各类
  局域网联机游戏"**（已用于官网 TDK/JSON-LD 与客户端文案）。
- 用户明确指定的外观基准：参考 `F:\Astral Game`（一个 Flutter 桌面启动器）的界面风格——
  浅色暖调、左侧图标栏、满幅主视觉卡片、底部动作条。该应用是编译后的 AOT 产物，
  无源码可抄，风格按截图实测还原（详见 DESIGN.md）。
- 不做的事（沿用既有取舍）：不做置顶迷你悬浮窗；不做需要玩家理解网络概念（端口映射/NAT 类型/
  隧道协议）才能完成主流程的界面——这些只出现在诊断里。

## Evidence on Hand

- 可运行的真实产品：`client/`（Electron）、`server/`（主控）、`web/`（官网 + 管理台），
  本机主控与打包版客户端都能起；截图与验证脚本在 `.cache/`。
- 真机数据：本机主控库里有 279 个注册用户、真实房间与流量记录（可用于真实内容的界面）。
- 文档：`README.md`（功能与架构事实）、`docs/*.md`（架构/部署/排障/安全/设计取舍）。
- **没有**：品牌插画、封面图、吉祥物、宣传视频、任何可用的美术素材；
  参考稿里的动漫封面与游戏封面图有版权，不得复制。凡是没有的素材一律不得假装存在。

## Product Principles

1. **一眼读完，然后切回游戏。** 界面的成败在于玩家切回来那 3 秒能不能拿到"能连吗、地址是什么、
   谁还没进来"。
2. **说人话，不说网话。** 主流程只出现玩家能理解的概念；延迟、NAT、隧道协议这类只进诊断。
3. **地址是这个产品的核心动作。** 建房之后最该被一眼看到、一点就复制的就是地址。
4. **稳链路优先于好看。** 任何视觉表达都不能挡住状态、错误与下一步动作。
5. **自己部署的人也要被照顾。** 主控是用户自己的机器，界面上给出的每个数字都要能指向可查的证据。

## Accessibility & Inclusion

- 正文对比度按 WCAG AA 校验（沿用既有令牌注释里的实测值），不得因为换配色而下降。
- 正文不小于 12.5px；不靠颜色单独传达状态（P2P/中继、在线/离线都要有文字或形状）。
- 浅色与深色都要可用：玩家的系统主题与"晚上关灯打游戏"的实际场景都可能出现。
